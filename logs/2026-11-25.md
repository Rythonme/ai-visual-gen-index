# 2026-11-25 工作日志 · AI 视觉生成资源榜

## 用户诉求

收到 GitHub 通知邮件「[Rythonme/ai-visual-gen-index] 部署榜单网站 workflow run — 部署榜单网站: All jobs have failed」，要求检查网站更新失败原因。

## 巡检结论（先排除误判）

| 检查项 | 结果 |
|---|---|
| 每日自动更新（11-16 ~ 11-25） | 10 次 schedule 全部 `success`，机器人自动提交 10 次；榜单数据正常到 2026-11-25 16:56 / W48 / 111 条 |
| 部署工作流历史 | 11-16 ~ 11-24 连续 9 次 `workflow_run` 部署全部 success；**仅 2026-11-25T08:56:40Z（北京 16:56）一次 failure**（run `45580744684`） |
| 站点文件 | 远端 `docs/` 7 个文件齐全（index.html / app.js / style.css / data.js / data.json / kanban.html / kanban_data.js） |
| 线上站点 | HTTP 200，但 `data.js` 停在 **2026-11-24 18:11**，比远端落后一天 → 确实因部署失败导致网页没更新 |
| 权限 | 日志显示 `Contents: read / Metadata: read / Pages: write`，权限正常 |

即：不是数据没更新、不是网站文件丢失、不是权限或代码逻辑错误，是**单次部署 job 失败**。

## 根因（来自失败 job 日志）

失败点仅在第 5 步「部署」（`actions/deploy-pages@v4`），前 4 步全部 success：

```
上传站点：Artifact github-pages has been successfully uploaded!
          Final size is 82620 bytes. Artifact ID is 15006606459
0.4 秒后
部署：Fetching artifact metadata for "github-pages" in this workflow run
      Found 0 artifact(s)
      ##[error] No artifacts named "github-pages" were found for this workflow run.
      ##[error] Fetching artifact metadata failed. Is githubstatus.com reporting
               issues with API requests, Pages, or Actions? Please re-run at a later time.
```

**判定**：GitHub Actions 的 artifact 服务是最终一致的，上传成功后 API 列表索引可能短暂不可见；`deploy-pages` 紧接着立刻按名字查 artifact，查到 0 个就直接失败。属平台侧偶发竞态/临时故障（官方日志自己建议稍后重跑），与本项目代码无关，因此前 9 天同样流程都成功。

附带观察（非本次失败原因，暂不处理）：runner 镜像已升级到 `ubuntu-26.04.1 / Node.js 24`，日志有 `Node.js 20 is deprecated ... forced to run on Node.js 24` 警告，涉及 checkout@v4 / configure-pages@v5 / deploy-pages@v4 / upload-artifact@v4。

## 修复内容

`.github/workflows/pages.yml`：

1. **新增「等待 artifact 元数据可见」步骤**（上传与部署之间）：调用 `GET /repos/{repo}/actions/runs/{run_id}/artifacts?per_page=100`，用 `jq` 筛出 `name == "github-pages" && expired == false`，最多轮询 24 次 × 5 秒（120 秒）；超时只发 warning 并继续部署，交由下一步兜底。
2. **新增「部署失败时自动重跑一次」步骤**：`if: failure() && inputs.retry != '1'`，等待 90 秒后用 `gh workflow run pages.yml --ref main -f retry=1` 触发一次重跑；`workflow_dispatch` 新增 `retry` 输入（默认 `0`），重跑时带 `1` 故不会再触发，**杜绝无限循环**。
3. `permissions` 增加 `actions: write`（读取 artifact 元数据 + 触发 dispatch）；job 增加 `timeout-minutes: 15`。
4. 保留原有 `workflow_run` / `push` / `workflow_dispatch` 三种触发与 `concurrency: pages`。

校验：PyYAML 6.0.2 严格解析通过（触发器、权限、dispatch 输入、6 个步骤、job 条件均正确）；两段内嵌 shell 用 `bash -n` 校验通过。

提交 `03bad0d fix: 等待 artifact 元数据可见 + 部署失败自动重跑一次，根治 Pages 偶发失败`。
