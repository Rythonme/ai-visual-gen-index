## 需求变更：新资源自动收录（用户 00:16 提出）

用户指出「新资源候选在以后的检索中自动更新收录，这样才能称为是实时更新榜单」。原设计「绝不自动收录、须人工核实」已按此推翻并重构。

### 分层设计（关键决策）

- **人工层** `data/tools.json`：90 条，**脚本永远只读、绝不改写**，符合「原始数据只读」约定。
- **自动层** `data/auto_tools.json`：由 `scripts/discover.py` 每次检索后增量写入，带 `auto_admitted` / `review_status: pending` / `admitted_at` / `source_query` 等审计字段。
- `build.py` 的 `load_tools()` 合并两层，id 或 GitHub 仓库冲突时**人工层优先**，因此维护者「转正」条目不会产生重复。
- 自动条目使用 `auto_admit.default_scores` 保守默认六维分（约 57.6 分），热度分仍走真实 GitHub API；实测综合分 55.1–63.7，**不会靠「新」冲进综合榜前列**（Top 5 未变）。

### 护栏（全部集中在 `data/config.json → auto_admit`）

Star ≥ 300、近 120 天新建、简介 ≥ 45 字、生图/生视频关键词白名单、黑名单（NSFW / 成人向 / 逆向 API / 接口封装 / Claude Code 工具箱 / SaaS 模板 / 教程合集 / 3D previs / ComfyUI 提示词工具等）、归档与 Fork 排除、两层清单去重、每轮最多 8 条、自动层上限 60 条。排序由纯 Star 改为**相关性优先**（关键词命中 + Star 对数 + 许可证 + `preferred_orgs` 官方机构加分 + 插件/评测榜降权），权重在 `relevance_weights` 公开。

护栏校准过程（实测）：首轮预览误收 `lemomo-ai/lemo-opuscar`（14k stars，实为 Claude Code 的提示词工具箱，描述含「with no video model」）、`uncensored-nsfw-ai-video-api`、`code-video-model/CodeVideoModel`（简介仅 30 字）、SaaS 模板与 3D rigging 项目；逐一核实官方描述后加入对应排除词与简介长度阈值，最终 32 个命中里**收录 8 个、拒绝 20 个**。
